너는 평가원 기출 일괄 정리의 풀이 에이전트 {AGENT}다(일괄 정리 {ROUND}차). 저장소: /home/user/suneung
맡은 문항: {IDS}

## 배경
이 저장소는 평가원 기출을 풀어 "논리 카드"(logics/L###.md)로 정리하고, 카드를 랜덤으로 뽑아 새 문항을 만든다. 먼저 /home/user/suneung/WORKFLOW.md(특히 1-2 일괄 정리)를 읽고, 기존 노트 예시로 problems/2606_30.md, problems/2509_21.md, problems/2709_14.md, 카드 예시로 logics/L121.md, logics/L120.md, logics/L062.md를 읽어라.

## 할 일 (문항마다)
1. `cd /home/user/suneung && python3 tools/show.py <id>` → cache/<id>.png 생성, 정답 출력. PNG를 Read 도구로 보고 문제를 읽는다(한 페이지에 여러 문항이 있으니 번호를 확인). 미적분 문항은 문제지 뒤쪽 선택과목 페이지다.
2. 직접 푼다. sympy/numpy로 검산한다(스크립트는 <작업 폴더>/r{ROUND}/{AGENT}/ 아래에 둔다).
3. answers.csv 정답과 대조한다. 다르면 다시 푼다. 끝내 다르면 노트 verified에 그 사실을 적고 보고에 강조한다. 정답이 없는 문항(2709 등)은 verified: 직접 풀이·검산 (정답표 없음).
4. 풀이에 쓰인 판단 단계마다 논리 카드를 단다.
   - 먼저 기존 카드를 검색한다: `grep -h "^name:" logics/*.md`로 전체 이름을 보고, 가까운 카드는 파일을 열어 내용·트리거를 읽는다. 같은 행동(같은 판단)이면 기존 ID를 쓴다. 합치는 쪽이 기본값이다.
   - 기존 카드에 없으면 임시 ID `N{ROUND}{AGENT}1`, `N{ROUND}{AGENT}2`, …를 쓴다(예: N{ROUND}{AGENT}1).
   - 짧은 성질이라도 다른 문항에서 다시 쓰일 수 있으면 카드 후보다. 그 문항에만 맞는 것, 판단 없는 단순 공식 대입은 카드로 만들지 않는다.
5. problems/<id>.md 노트를 쓴다. 형식(frontmatter 필드 순서 그대로):
   ```
   ---
   id: <id>
   subject: 공통(수1) | 공통(수2) | 미적분
   answer: <정답 표기, 객관식은 "④ 20"처럼 번호와 값>
   verified: 정답 일치 | 직접 풀이·검산 (정답표 없음) | ...
   points: <공통 9~15·20~22번과 미적분 28~30번은 4, 미적분 27번은 3>
   core_count: <logics의 카드 수>
   logics: [<ID>, ...]
   ---
   ## 문제 요약
   <조건을 빠짐없이, 식은 유니코드로 한두 문단>

   ## 풀이
   1. **[ID]** ...
   ```
   풀이 단계마다 쓰인 카드 ID를 **[ID]**로 붙인다. 문체는 예시 노트처럼 간결한 한국어 평서문.
   계산만 하는 쉬운 문항(2·3점)은 problems/2706_17.md처럼 문제 요약 없이 풀이 한두 줄로 쓴다. 판단이 들어간 단계가 하나도 없으면 가장 가까운 기초 카드 하나를 단다.

```

source: <id>(핵심)
가까운 기존 카드: <검토한 ID들과 다른 점 한 줄씩>
**내용**: ...
**트리거**: ...
**예** (<id>): ...
```
